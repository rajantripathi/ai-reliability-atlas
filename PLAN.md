# AI Reliability Atlas: implementation and publication plan

## Product acceptance
An interactive field lab for recruiters, technical readers and research collaborators. Visitors must be able to inspect actual source artifacts, compare historical configurations, replay recorded decisions, exercise a deterministic policy, and download the evidence. No interaction may imply a new model execution when it is a replay or teaching example.

## Available resources
SOAS: 200-item comparison, 100 Uzbek / 100 English; published 400-row pilot is a separate release. CaseLens: reported 100 pages / 339 questions, three retrieval configurations. Visual Release Gate: 24 briefs, 8 reused images, provisional author labels, 19 completed outputs, 5 provider errors. Assets from its original CC-BY-4.0 sample pack.

## Delivery order
1. Import minimal public source snapshots with SHA-256 and commit references.
2. Build three interactive experiment panels, source drawer, full run ledger and practical policy sandbox.
3. Validate arithmetic, source integrity, policy combinations, rendered behaviour, mobile layout and accessibility.
4. Prepare a share card, five-page PDF carousel, demo recording, README and launch/profile drafts.
5. Deploy a private review version. Public promotion is a separate explicit publication step; do not update LinkedIn or the GitHub profile automatically.

## Claims and limits
- Corpus repair was targeted using evaluation-linked missing sources. Do not call the gain general multilingual accuracy.
- Metadata-only is not a strong OCR baseline. Do not claim VLM superiority to OCR.
- Policy decisions depend on model observations and selected rules. Deterministic code cannot guarantee that incorrect observations never lead to approval.
- Gate agreement is against provisional author labels; never describe it as validated accuracy or proof of safety.
- Synthetic policy scenarios show actual code behaviour, not measured prompt-injection resilience or live LLM outputs.
- Scores such as 9/10 describe aspirations, not evidence of recruiter outcomes.

## Definition of done
Runnable site, downloadable source bundle and manifest, successful validation, desktop/mobile captures, carousel, recording, launch copy, and an explicit publication status. If an external service prevents deployment, retain the tested local deliverable and report the exact blocker.
